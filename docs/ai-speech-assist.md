# AI 口說輔助（登台展演）— 第一階段實作與評估

依據：專案根目錄 `ai_assistant_input`（AI 語音對話需求）。日期：2026-11-20。

## 1. 需求對照

| 需求 | 做法 | 用 AI？ |
|---|---|---|
| 正確回答不介入，直接延續劇本 | 判斷為「正確」時學生畫面不顯示任何東西 | — |
| 輕微錯誤不打斷 | 判斷為「輕微」只寫進紀錄，學生畫面不顯示 | — |
| 嚴重影響理解才即時修正 | 判斷為「嚴重」才在學生 iPad 顯示提示卡 | ✅ |
| 依 CEFR 程度判斷 | 任務程度（preA1-A1／A1／A1-A2／A2-B1）放進提示詞，低程度從寬 | ✅ |
| 回饋簡短 | 提示卡只有一行標題＋關鍵資訊（句型開頭或正確的字） | — |
| 保存常見錯誤 | 後端 SQLite `speech_feedback`，老師端「紀錄」看每位學生統計與逐句紀錄 | — |
| 沉默 5–8 秒顯示文字提示 | 沿用既有分級提示（沉默 6 秒升一級，老師可開關「自動」） | — |
| 只說出部分句子 → 句型補充提示 | 「接著說下去」：從學生說到的地方多給一個字，其餘留空格 | ✅ |
| AI 不代答、不自動切換發言者 | 判斷結果只顯示提示；換句仍由學生按「我說完了」或老師控制 | — |
| 老師可隨時手動控制 | 老師端開關「AI 口說輔助」、上一句／下一句／跳句／暫停照舊 | — |

六大偵測項目：

| 項目 | 回饋方式 | 實作 |
|---|---|---|
| 中文／中英混用 | 鼓勵重新以英文表達 | ✅ 「試著用英文說說看，可以這樣開頭」＋英文句型開頭（一律提示） |
| 長時間停頓 | 提供單字或句型提示 | ✅ 既有分級提示（意思→開頭→重組→完整） |
| 發音錯誤 | 正確發音示範、跟讀 | ⏸ 第二階段（既有「完整」級有「聽一次」可示範） |
| 單字錯誤 | 提示正確單字 | ✅ 「換這個字試試」：~~說錯的字~~ → 正確的字 |
| 句子不完整 | 句型開頭、引導補完 | ✅ 「接著說下去」 |
| 完全沒有回應 | 主動提問、提供簡單選項 | ✅ 輪到自己 10 秒都沒出聲：「你想說的是哪一句？」三選一（不用 AI） |

## 2. 運作流程

```
學生 iPad（輪到自己、老師開了 AI 口說輔助）
  ├─ 錄下 LiveKit 已發布的麥克風音軌（不另開麥克風）→ 16 kHz 單聲道 WAV，最多 20 秒
  ├─ 開口後停住 2.5 秒 → POST /api/rooms/:roomId/speech-judge（顯示結果）
  ├─ 按「我說完了」且上次判斷後又說了話 → 再判斷一次（只記錄）
  ├─ 每句最多 3 次；每位學生每分鐘最多 20 次（後端限制）
  └─ 10 秒都沒出聲 → 三選一選項（本機產生，不送 AI）

後端
  ├─ Gemini（預設 2.5 Flash-Lite，失敗退 2.5 Flash）聽錄音：逐字稿、語言、漏掉的字、說錯的字、意思有沒有傳達
  ├─ 固定規則決定嚴重程度（中文、意思沒傳達 → 嚴重；有小錯 → 輕微；沒問題 → 正確）
  └─ 寫入 speech_feedback（含 token 與估計費用），回傳判斷

老師端
  ├─ 登台展演卡：「🎙AI 口說輔助」開關（預設關）＋「紀錄」
  ├─ 目前這句的 AI 判斷（嚴重程度、問題、逐字稿、說錯／漏掉的字）
  └─ 紀錄視窗：判斷次數、錄音總長、token、估計費用；每位學生統計；逐句紀錄
```

主要程式：`backend/src/ai/speechJudge.ts`、`backend/src/speechRoutes.ts`、`backend/src/db/speechFeedbackRepo.ts`、
`frontend/src/utils/speechAssist.ts`、`frontend/src/hooks/useTurnAudioClip.ts`、`frontend/src/hooks/useScriptTurnStudent.ts`。

## 模擬學生回答頁

入口：老師首頁下方的「模擬學生回答：試用 AI 口說輔助」，會開新分頁；也可以直接開 `/?screen=speech-sim`。

- **左欄**：選劇本（內建模板）、學生程度、段落和台詞。
- **中間**：學生 iPad 的發言畫面（4:3），和上課時看到的一模一樣。
  - 「開始回答」會用電腦麥克風錄音；按「停止並判斷」或 iPad 上的「我說完了」就送 AI 判斷。
  - 可以切換分級提示（意思／開頭／重組／完整）。
  - 「不用 AI 預覽」直接套一個範例結果（正確／輕微／說中文／說錯字／沒說完／沒有回應），只看畫面、不花用量。
- **右欄**：判斷結果和這次試用的紀錄。
  - 判斷結果包含：嚴重程度、聽到的內容、語言、問題、說錯和漏掉的字、模型、延遲、token、費用。
  - 試用紀錄列出每一次判斷，並加總費用。
- **限制**：試用判斷走 `POST /api/speech-judge/preview`，不需要開課堂，也不存成紀錄。所有人共用一個上限：每分鐘最多 30 次。

## 3. 實測評估

腳本：`backend/scripts/speech-judge-eval.mts`（Windows 內建語音合成 11 種情況，送真的 Gemini）。

```
cd backend && NODE_OPTIONS=--use-system-ca EVAL_GAP_MS=7000 npx tsx scripts/speech-judge-eval.mts
```

| 情況 | 2.5 Flash-Lite | 2.5 Flash |
|---|---|---|
| 完全正確（2 句） | ✓ 正確 | ✓ 正確；1 次把 "How about this hat?" 聽成 "How about this?" → 判輕微（不打擾） |
| 文法小錯（this jeans） | ✓ 正確 | ✓ 輕微 |
| 漏小字（Nice meet you） | ✓ 輕微 | ✓ 輕微 |
| 只說前半句 | ✓ 輕微 | ✓ 嚴重（接著說） |
| 說兩個字就停 | ✓ 嚴重（接著說） | ✓ 嚴重 |
| 關鍵字說錯（city → cat） | ✓ 嚴重（換字） | ✓ 嚴重 |
| 顏色說錯（red → blue） | ✓ 輕微 | ✓ 輕微 |
| 整句說中文 | ✓ 嚴重（中文）；1 次逐字稿被翻成英文，但仍判出中文 | 限流沒測到 |
| 中英混用（I love 牛肉麵） | ✓ 中文 | ✓ 嚴重（中文） |
| 完全沒有聲音 | 限流沒測到 | ✓ 沒有回應 |

- 兩個模型各跑兩輪，扣掉被限流的，32 次判斷中 31 次符合預期；唯一不符合的是聽漏一個字而判「輕微」，輕微不會打擾學生。
- **延遲**：每次約 2.0–3.5 秒（平均約 2.5 秒）。所以只在「停住之後」給提示，不做邊說邊糾正。
- **token**：每次輸入 450–570（其中音訊 80–190，約每秒 32 個）、輸出 40–125。
- **限制**：合成語音清楚、沒有噪音，是理想情況；真實學生（口音、教室噪音、iPad 麥克風）要再驗證。

## 4. 完成一次劇本對話的 AI 用量估計

實測每次判斷的費用：**2.5 Flash-Lite 約 US$0.0001**、**2.5 Flash 約 US$0.0003–0.0004**。

假設：「認識新同學」4 人版 32 句；說得順的句子按「我說完了」判斷 1 次，卡住的句子 2–3 次，平均每句約 1.3 次，一次演出約 42 次判斷。

| | 2.5 Flash-Lite（預設） | 2.5 Flash |
|---|---|---|
| 一次演出（約 42 次） | 約 US$0.004（約 NT$0.13） | 約 US$0.015（約 NT$0.5） |
| 一個班（8 組輪流演出） | 約 US$0.035（約 NT$1.1） | 約 US$0.12（約 NT$4） |
| 一學期（10 個班 × 6 堂劇本課） | 約 US$2（約 NT$70） | 約 US$7（約 NT$230） |
| 錄音量 | 一次演出約 3–4 分鐘錄音、約 7,000 個音訊 token | 同左 |

服飾店的三個模板每步 5–9 句、共約 22 句，用量約是上表的 70%。

## 5. 上線前要注意

1. **一定要用付費層金鑰**。實測這把金鑰是免費層：連續送十幾次就遇到 429（超過每分鐘／每日上限），課堂上會判斷失敗。另外，免費層送出的資料可能被用來改進模型，學生的聲音不該走免費層。付費層的上限遠高於一間教室的需求（一間教室同時只有一位發言者，每分鐘最多約 20 次）。
2. **學生錄音會送到 Google 判斷**。後端不保存錄音，只保存逐字稿與判斷結果。建議在學校的家長同意書或隱私說明中註明。
3. **iPad 實機還沒驗證**：
   - `AudioContext` 在 iPad 上可能一開始是暫停狀態（學生加入課堂時已經點過畫面，通常能恢復）。
   - 跟 LiveKit 共用同一條麥克風音軌，沒有另外開麥克風，所以不會搶麥克風。
4. **判斷失敗不影響上課**：失敗時學生畫面不顯示 AI 提示，分級提示照常運作。
5. 預設模型可以用環境變數 `GEMINI_JUDGE_MODEL` 調整（逗號分隔，依序嘗試）。

## 6. 第二階段（未做）

- **發音評估**：Gemini 只能粗略指出「哪個字聽起來不對」，沒辦法穩定給分數。要精準評分，需要另外接專門的發音評分服務，每句約 US$0.001。
- **個人化口說回饋**：把 `speech_feedback` 的常見錯誤接到課後練習，例如依常漏、常錯的字出練習題。
